## 🧭 How I Approach Infrastructure Work

```text
Understand → Assess → Collect Evidence → Isolate Root Cause
          → Design Lowest-Risk Fix → Implement → Validate
          → Monitor → Document → Prevent Recurrence
```

For production incidents, I prioritize evidence preservation, controlled changes, rollback awareness and post-change validation instead of repeated trial-and-error restarts.

## 📚 Evidence Structure

Each major project is designed to answer the questions a client or technical reviewer actually cares about:

- **What problem does this solve?**
- **What environment/components are involved?**
- **How is the problem diagnosed?**
- **What commands/configuration demonstrate the work?**
- **What is the root cause?**
- **What is the remediation and why is it safe?**
- **How is success validated?**
- **What operational/security considerations remain?**

Where applicable, projects also include architecture diagrams, troubleshooting flows, automation examples, validation steps and runbook-style documentation.
